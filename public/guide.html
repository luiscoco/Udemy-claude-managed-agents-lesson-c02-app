YOUR LEARNING GOALS

What you will learn

One warehouse task, two agent surfaces. Explain what changes and what remains the host’s responsibility.

01

Choose the agent surface

Compare the Messages API with Managed Agents using the same reservation task. Identify who drives iteration and who retains conversation history.

02

Keep the effect on the host

Both paths call the same local reserveStock handler. The model requests an operation; the host validates inputs and changes the seeded inventory.

03

Build a manual tool loop

Read tool_use blocks, execute each requested call, append assistant calls and correlated tool_result records, then request the next model response.

04

Answer managed custom tools

Create a session, open observation before sending a prompt, handle agent.custom_tool_use, and correlate the result with custom_tool_use_id.

05

Understand setup and session state

Create or reuse an agent and environment. Distinguish a reusable configuration, a new session, the browser SSE stream, and provider events.

06

Verify success and partial failure

Inspect reservation IDs, error results, final stock, and reported stop reasons. A model summary or a Done badge is not proof that every item was reserved.

By the end: you can trace the manual and managed tool-result protocols and justify the result using host evidence.

FROM SETUP TO YOUR FIRST COMPARISON

How to run this application

Follow these PowerShell steps. Keep resource setup separate from repeated application runs.

  1. Open the C02 application folder

    Use Node.js 24 or newer with npm. From the presentations folder:

    cd .\lesson-c02\lesson-c02-app
npm install

    If your terminal is already in the folder containing this app’s package.json, run only npm install.

  2. Create .env without overwriting it

    Preserve existing configuration. Otherwise copy the template, then open .env in your editor:

    if (!(Test - Path.env)) {
  Copy - Item.env.example.env;
}
    ANTHROPIC_API_KEY=your_api_key
CLAUDE_MODEL=claude-opus-5-5
PORT=3000

    The API key stays on the server. CLAUDE_MODEL selects the model; use one available to your workspace. C01 and C02 both default to port 3000, so stop the other app or choose a different PORT.

  3. Prepare the managed resources once

    The manual flow needs only API access. For the managed flow, your workspace also needs Managed Agents access. If you do not have suitable resources:

    npm run managed:setup

    This creates an environment and an agent with the reserveStock custom tool, then writes .managed-ids.json. Save and reuse those resources. To select compatible existing resources, use MANAGED_AGENT_ID and MANAGED_ENVIRONMENT_ID in .env instead. The agent must expose the custom tool expected by this app.

  4. Start the app and open the browser

    npm start

    Wait for the ready address, then open http://127.0.0.1:3000. npm run dev starts the same server. Keep the terminal open and restart after editing .env.

  5. Run the same request through both surfaces

    Choose Happy path and click Run both. The app runs manual first, then managed, resetting the seed inventory for each flow. Follow the host tool calls in both columns. You can also run either column separately. Each run uses the real Claude API and may incur charges.

    Reserve 2 astronaut mugs (SKU-100) and 1 rocket hoodie (SKU-200), then summarize.

  6. Inspect evidence and compare failures

    The happy path should leave 10 mugs, 2 hoodies, and 0 lamps. Read tool results and the final stock table. Try Out of stock and Partial failure: a failed reservation should not subtract stock, but an earlier successful reservation is not rolled back.

    Use one run at a time; inventory is shared process memory, not a durable warehouse. Visiting a guide does not cancel remote work. This sample has no interrupt control; do not retry an uncertain run blindly. Ctrl+C stops the local server.
